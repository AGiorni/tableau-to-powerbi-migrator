The graph

One LangGraph StateGraph runs every migration, from the CLI and from tests alike. Nodes read MigrationState and return partial updates; routers pick the next node by name. The chat model and run flags travel separately in MigrationContext.

Worksheet → visual

The densest logic in the codebase (_map_worksheet in mapping/visual_mapper.py). Each worksheet runs through these checks in order. The first one that matches decides the visual.

Dashboards

Each Tableau dashboard becomes one more page. Its worksheet zones get a copy of that worksheet's visual, rescaled from Tableau's 100 000 × 100 000 grid to the 1920 × 1080 canvas. Its filter zones become slicers, but only for columns (a filter on a measure is noted in the report) and only once per field.

Page order

All worksheet pages come first, in workbook order, then all dashboard pages. Page and visual folder names are random 20-character ids, so two runs never produce identical paths.

Where the LLM is called

Two places only, both reading the chat model from runtime.context. Both are grounded on the model or the catalog, both re-check the answer in code, and both fall back to a deterministic result, so a missing or misbehaving LLM never produces a broken file.

CallAskedAnswer checked byWithout an LLM
translate_expressions ⇄ validate_expressions One Tableau formula → one DAX expression, given every table and column name. validate_expressions: empty or unbalanced → kept pending and sent back on the repair route with the reason, up to max_translation_attempts (default 2). Unknown references → warning only. no_llm route → flag_untranslated: stays BLANK(), warning. Budget spent → ERROR, still BLANK().
LLMVisualRouter For worksheets no rule matched: pick a visual type and assign fields to roles, as JSON. Rebuilt from field names it was given, run through enforce_wells, rejected if the type is unknown or a required role is empty. DefaultRouter: the worksheet is skipped with a warning.

env: T2PBI_AZURE_OPENAI_ENDPOINT (required) · _DEPLOYMENT (gpt-4o) · _API_VERSION · _API_KEY (else Entra ID via DefaultAzureCredential) · temperature 0

Gotchas

Behaviour that the code does but nothing else tells you. Red items are not in BACKLOG.md yet; grey ones are.

  • Validation never stops anythingbacklog

    Validation errors are only written to the report. The files are still written and the CLI exits 0, so a script can't tell a clean run from a broken one.

    graph/nodes.py validate_model · cli.py _run_migrate · now a one-edge change: a router after validate_model

  • Every calculated field becomes a measurebacklog

    A dimension-role calc, such as a calculated category or bucket, becomes a measure too, so it can't sit on an axis or in a slicer the way it did in Tableau.

    mapping/model_mapper.py _map_measures

  • Out-of-date skip messagenot in backlog

    The "no mappable fields" warning still gives "a map or Measure Names sheet" as examples, but both are handled now.

    mapping/visual_mapper.py map_visuals

  • Sort is always descending by the first measurebacklog

    The sort direction is never read from the workbook.

  • Parameters are droppedbacklog

    Parsed with their current and allowed values, then never used.

  • Unsupported connections give empty tablesbacklog

    Snowflake, Oracle, BigQuery, extracts and others: structure only, no data.

  • Don't "fix" the PBIR format constants

    Report version 2.0.0, .platform files, no BOM, powerBI_V3, visual container 2.12.0: each was found through a rendering failure. The table is in docs/DEVLOG.md.

Where things live

cli.pyFlags --out, --no-llm, --no-validate, --report → a MigrationContext; prints counts.

mapping/powerquery.pyM source per connection type.

mapping/visual_mapper.pyWorksheet and dashboard → pages and visuals.

mapping/visual_router_llm.pyLLMVisualRouter.

validate/model_validate (tables, partitions, relationship columns), dax (brackets, references), tmdl_cli (TOM, via tools/tmdl-validate), pbir_cli (powerbi-report-author).

Commands
# run, no LLM
t2pbi migrate samples\input\x.twb --out out --no-llm

# with a JSON issue report
t2pbi migrate x.twb --out out --report out\report.json

# checks (both must pass)
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests scripts

# refresh the visual catalog
python scripts\refresh_visual_catalog.py

# build the TMDL validator (needs .NET)
dotnet publish tools\tmdl-validate -c Release -o tools\tmdl-validate\bin\publish

# fidelity score of the samples
python scripts\fidelity.py

# output unchanged? (run on both revisions)
python scripts\snapshot_outputs.py snap a.json
python scripts\snapshot_outputs.py compare a.json b.json
